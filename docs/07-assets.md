downloaded from an openly licensed source. **Forty-two are copied from the
reference site**, each by explicit request — the ten auth images, the sidebar
promo, the three home banners, and the twenty-eight pieces the `/loyalty` sheet
is made of. They are listed as such below and in
[The exceptions](#the-exceptions). This document records where every file came
from so you can audit it before shipping.

## Fonts

The reference site's `.bitcasino` theme declares:

```css
--font-primary: "DM Sans";
--font-secondary: "Space Grotesk";
```

Both are **SIL Open Font License 1.1** — free to use, embed, and redistribute
in commercial work. `npm run fonts:fetch` pulls the latin subset as woff2 and
self-hosts them, which avoids a third-party request on first paint and keeps
the app working offline.

The same CSS bundle also references **Averta Std**, used by sibling brands.
Averta is a commercially licensed typeface — it is **not** downloaded, not
committed, and not referenced anywhere in this project. If you want it, buy a
web licence from the foundry.

> Known minor inefficiency: DM Sans ships as a variable font, so the 400/500/700
> files Google returns are byte-identical (~37 KB each, ~74 KB wasted). Fine for
> development. To fix, request one file and declare `font-weight: 400 700` on a
> single `@font-face`.

## Generated artwork

`scripts/art.mjs` holds the drawings; `scripts/generate-assets.mjs` is the
pipeline that reads the catalog and writes the files. Each item's slug is
hashed (FNV-1a) into a palette and an emblem, so output is stable across runs
but varied across items — re-running yields byte-identical files.

A game tile is a dark gradient base, a soft glow, a category emblem, and the
title and studio set into the artwork rather than captioned beneath it. Hues
are quantised to a fixed set rather than drawn from the full wheel, and each
category picks from three on-theme emblems, so a rail of twelve tiles reads as
a catalogue instead of a wall of random gradients.

Game thumbnails are authored at **420 x 564** — the same ratio the reference
site uses — so swapping in real artwork needs no CSS change.

App icons are real PNGs. The script contains a small PNG encoder (zlib
`deflateSync` + CRC32 + IHDR/IDAT/IEND) and draws the mark with a
signed-distance function for antialiased edges, so there is **no native image
dependency** anywhere in the toolchain.

Replacing them: overwrite the files, or edit `scripts/art.mjs` (`gameThumb` /
`providerLogo` / `promoArt` / `themeArt`, or the `EMBLEMS` table) and re-run
`npm run assets:gen`. Generated output is committed, so a fresh clone works
without running either script.

## What was deliberately not taken

The reference site serves assets from `heathmont.imgix.net`, `hub88.imgix.net`
and `cdn.coingaming.io`. With one exception — the auth screens, below — none of
it is used here:

| Asset | Why not |
| --- | --- |
| Logo, wordmark, `favicon/bc-*.png` | Registered trademarks. Copying them into a working casino UI is brand impersonation, not a UI study — the single clearest legal and ethical line in a project like this. |
| Game thumbnails | Copyrighted artwork licensed to the studios that made the games. The operator cannot sublicense it, so neither can you. |
| Studio logos | Third-party trademarks. |
| Marketing and SEO copy | Copyrighted text. |

this is the operator's copyrighted marketing artwork, and it has to be
replaced before this goes anywhere real.**

## Before you ship

1. Replace `Logo.jsx` with your own mark.
2. Re-run `npm run assets:gen` after editing the icon generator, so the
   favicon and app icons match your brand.
3. Replace the placeholder catalog with real, licensed game artwork.
4. Replace everything in `images/auth/` and the copy on `/login` and
   `/register` — that pair is currently a verbatim clone of the reference.
5. Replace everything in `images/loyalty/` and the copy in `data/loyalty.js` —
   `/loyalty` is the other verbatim clone.
5. Replace `images/sidebar-promo.avif` and the three rasters in
   `images/banners/` — all four are the reference's marketing artwork. The
   banners are a one-line revert: point `HOME_BANNERS[].art` back at the
   generated `.svg` files sitting beside them.
4. Update `manifest.webmanifest` name, colours, and the `<title>` in
   `index.html`.
5. Keep the footer's "not a real operator" disclaimer until it stops being
   true — and if it does stop being true, read
   [09 — Roadmap](./09-roadmap.md) first.
