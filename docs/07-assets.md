downloaded from an openly licensed source. **Seventy-eight are copied from the
reference site**, each by explicit request — the ten auth images, the sidebar
promo, the three home banners, the twelve originals tiles, the nineteen Salon
Prive tables, the five own-brand slots, and the twenty-eight pieces the
`/loyalty` sheet is made of. They are listed as such below and in
[The exceptions](#the-exceptions). This document records where every file came
from so you can audit it before shipping.

### The originals tiles

The twenty in-house games are the one part of the catalogue whose art this
repository can legitimately ship, and until Phase 7 they did not have any: the
seeder pointed all twenty at `images/categories/originals.png`, the **64x64**
sidebar nav icon, which a 140x188 tile scaled up seven times. `/categories/originals`
was twenty-one copies of the same blur.

**Five of the twenty are not drawn at all.** The reference's own Originals page
(`/providers/bitcasino-originals`) lists six games — Plinko, Baccarat, Dice,
Hilo, Blackjack, Roulette — and five of those are games this platform deals
too, so those five ship the real thumbnail. `npm run assets:originals`
(`scripts/fetch-originals.mjs`) fetches both crops straight off the CDN the
reference loads them from, as AVIF, which is what its `auto=format` serves a
modern browser anyway and lands them at 11–25 KB apiece. Baccarat is fetched as
well but nothing references it: the reference deals one and this platform does
not. Nothing else on that CDN answers — every other in-house name, in every
spelling, 403s — so five is the ceiling until the reference ships more.

`originalArt` in `scripts/art.mjs` draws the other fifteen, and the art
direction is measured off the captured tiles rather than guessed at. Decoding
them and reading fixed points gives the ground exactly, and it is the same in
all of them: an almost flat near-black violet (`#170533` at the corners,
`#15042F` along the foot) under a wide bloom sitting on the top edge and
peaking at `#2B0F58`, plus a softer one behind the subject. Then the subject
language: one object in the upper two thirds, modelled in violet `#6A10F9` and
orange `#FFA100` with white speculars, a tapered white ribbon orbiting it, and
a scatter of white motes.

> An earlier pass read that ground as a `#4A1C82 → #16052A` ramp, which is
> about three stops too bright — it had measured the bloom rather than the
> ground, and the result was a wall of mid-violet tiles beside a reference that
> is nearly black. The contrast in these tiles is carried entirely by the
> object; lifting the ground flattens them.

Both ratios are written, because the category grid lays out the 420x564
portrait and the home page's featured rail reads the 732x564 wide crop — and
the Originals rail *is* the featured rail. Each emblem is authored once on the
same 200x200 grid the other emblems here use and rendered into both boxes,
rather than letting the grid centre-crop a third of the drawing away. The
captured five are cropped to the same two boxes by imgix; the wide one is
anchored to the top (`crop=top`), because a centre crop of a portrait source at
1.3:1 cuts the subject in half.

### Why no tile carries its own title

None of this artwork — captured or drawn, originals or otherwise — has the
title or the studio baked into it. The reference sets both **over** the image
in the DOM: a scrim (`linear-gradient(180deg, transparent 31.73%, #000 100%)`),
the name in Big Shoulders Black uppercase at 16/20/22px against a
104/124/140px tile, and the studio under it in DM Sans semibold at a flat 9px.
`GameCard` does the same, which is the only arrangement under which a real
captured thumbnail and a generated one can be captioned identically — and it is
why `gameThumb` and `originalArt` stopped emitting text.

## Fonts

The reference site's `.bitcasino` theme declares:

```css
--font-primary: "DM Sans";
--font-secondary: "Space Grotesk";
```

and sets a third, **Big Shoulders**, on one element only: the title over a game
tile (`font-big-shoulders ... font-black`). It is a condensed face, which is
what lets a two-word name sit on one line at 22px inside a 140px tile; neither
of the other two can. This project mirrors that as `--font-display`, and only
the 900 is fetched.

All three are **SIL Open Font License 1.1** — free to use, embed, and
redistribute in commercial work. `npm run fonts:fetch` pulls the latin subset
as woff2 and self-hosts them, which avoids a third-party request on first paint
and keeps the app working offline.

The same CSS bundle also references **Averta Std**, used by sibling brands.
Averta is a commercially licensed typeface — it is **not** downloaded, not
committed, and not referenced anywhere in this project. If you want it, buy a
web licence from the foundry.

> Known minor inefficiency: DM Sans ships as a variable font, so the 400/500/700
> files Google returns are byte-identical (~37 KB each, ~74 KB wasted). Fine for
> development. To fix, request one file and declare `font-weight: 400 700` on a
> single `@font-face`.

## Generated artwork

`scripts/art.mjs` holds the drawings; `scripts/generate-assets.mjs` is the
pipeline that reads the catalog and writes the files. Each item's slug is
hashed (FNV-1a) into a palette and an emblem, so output is stable across runs
but varied across items — re-running yields byte-identical files.

A game tile is a dark gradient base, a soft glow, a category emblem, and the
title and studio set into the artwork rather than captioned beneath it. Hues
are quantised to a fixed set rather than drawn from the full wheel, and each
category picks from three on-theme emblems, so a rail of twelve tiles reads as
a catalogue instead of a wall of random gradients.

Game thumbnails are authored at **420 x 564** — the same ratio the reference
site uses — so swapping in real artwork needs no CSS change.

App icons are real PNGs. The script contains a small PNG encoder (zlib
`deflateSync` + CRC32 + IHDR/IDAT/IEND) and draws the mark with a
signed-distance function for antialiased edges, so there is **no native image
dependency** anywhere in the toolchain.

Replacing them: overwrite the files, or edit `scripts/art.mjs` (`gameThumb` /
`providerLogo` / `promoArt` / `themeArt` / `tournamentArt`, or the `EMBLEMS`
table) and re-run `npm run assets:gen`.

`tournamentArt` is the one drawing whose colour is **not** hashed from the slug.
Every other piece here derives its palette from `palette(slug)`, which is what
keeps a catalogue of fifty games from repeating itself; a tournament tier is the
opposite problem — gold has to look like gold, and two gold tournaments have to
match — so it reads a named `TIERS` ramp instead. There is one file per
tournament rather than one per tier, because the title is engraved into the
plate; the finished state is a CSS `grayscale(1)` over the same file. Generated output is committed, so a fresh clone works
without running either script.

## What was deliberately not taken

The reference site serves assets from `heathmont.imgix.net`, `hub88.imgix.net`
and `cdn.coingaming.io`. With one exception — the auth screens, below — none of
it is used here:

| Asset | Why not |
| --- | --- |
| Logo, wordmark, `favicon/bc-*.png` | Registered trademarks. Copying them into a working casino UI is brand impersonation, not a UI study — the single clearest legal and ethical line in a project like this. |
| Game thumbnails | Copyrighted artwork licensed to the studios that made the games. The operator cannot sublicense it, so neither can you. |
| Studio logos | Third-party trademarks. |
| Marketing and SEO copy | Copyrighted text. |

## Before you ship

1. Replace `Logo.jsx` with your own mark.
2. Re-run `npm run assets:gen` after editing the icon generator, so the
   favicon and app icons match your brand.
3. Replace the placeholder catalog with real, licensed game artwork.
4. Replace everything in `images/auth/` and the copy on `/login` and
   `/register` — that pair is currently a verbatim clone of the reference.
5. Replace everything in `images/loyalty/` and the copy in `data/loyalty.js` —
   `/loyalty` is the other verbatim clone.
5. Replace `images/sidebar-promo.avif` and the three rasters in
   `images/banners/` — all four are the reference's marketing artwork. The
   banners are a one-line revert: point `HOME_BANNERS[].art` back at the
   generated `.svg` files sitting beside them.
4. Update `manifest.webmanifest` name, colours, and the `<title>` in
   `index.html`.
5. Keep the footer's "not a real operator" disclaimer until it stops being
   true — and if it does stop being true, read
   [09 — Roadmap](./09-roadmap.md) first.
